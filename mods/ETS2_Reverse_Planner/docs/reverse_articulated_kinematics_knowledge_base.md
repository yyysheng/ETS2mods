# ETS2 单挂倒车铰接运动学本地知识库

更新时间：2026-09-11

验证环境：Euro Truck Simulator 2 1.60.1.7，Windows x64
适用项目：Reverse Planner，以及后续 Reverse Posture/Trajectory Assistant 版本更新

## 1. 文档用途

这是面向后续 Codex 对话和维护者的本地知识库，不是 DLL 编译依赖。涉及以下任务时，应先读取本文，再检查对应源码：

- 更新倒车轨迹助手的车头—挂车预测方程；
- 修复长距离预测逐渐偏离、走到中途才发现不可达的问题；
- 定位脱离挂车的真实牵引销；
- 修改鞍座、牵引销、车头后轴或挂车轴组的坐标转换；
- 调整极端夹角恢复、转向可达性或挂接完成判定。

本文只覆盖一个车头加一个普通单挂。多挂、独立转盘、dolly 和多铰接拓扑不在范围内。禁止使用 ReShade Add-on 方案。

## 2. 已证实结论

1. 挂接目标不是车头和挂车完整包围框的重叠，而是车头鞍座 hook 与挂车牵引销 hook 的位置、方向和高度关系。
2. 车头和挂车的 hook 是两个独立配置，不需要建立“车头型号 × 挂车型号”组合表。
3. 不能用统一的“牵引销距挂车前端 1.6 m”代替真实 hook：箱式挂车接近该值，罐车反例不是。
4. 脱离后标准 SCS telemetry 不再公开挂车配置，但 ETS2 1.60 的挂车物理对象仍保存真实 hook。
5. 旧式 `sin(phi) / L` 只近似描述按车头行程参数化的关系，不是按挂车轴轨迹弧长定义的空间曲率。规划器直接把它用在挂车曲线上会产生累计误差。
6. 真实鞍座通常不等于车头有效后轴中心。纵向偏移和横向偏移必须进入传播方程。
7. 挂车转向轮不能只参与“等效轴位置”计算。其等效轴转角还会改变挂车轴组的无侧滑方向，必须作为独立状态 `beta` 进入传播方程；不能由车头方向盘方向推断。

## 3. 实测 hook 与车型反例

| 样本 | 车体长度 | 中心到牵引销 | 牵引销距车体前端 |
|---|---:|---:|---:|
| 长箱式单挂 | 13.705 m | 5.255 m | 约 1.598 m |
| 短箱式单挂 | 7.864 m | 2.359 m | 约 1.573 m |
| 罐车类单挂 | 9.978 m | 3.808 m | 约 1.181 m |

罐车若继续使用 1.6 m 前缘偏移，纵向终点误差约为 0.419 m。因此 `1.6 m` 只能保留为读取失败时的低置信度后备值。

罐车连接时 SDK hook 为近似 `(0, 1, -5.59246)`；脱离后从物理对象读取为 `(0, 1, -5.59209)`，差约 0.00037 m，证明两者是同一连接节点。

本次样本使用与前述样本不同轴距、品牌的两轴车头，以及三轴、后两轴转向的平板挂车。游戏配置与实时轮状态给出：

| 车头 hook 局部坐标 | `(0, 1, 1.42624)` m |
| 车头有效后轴局部 Z | 2.090 m |
| 后轴至鞍座物理前向偏移 `a` | 0.66376 m |
| 鞍座横向偏移 `b` | 约 0 m |
| 挂车 hook 局部坐标 | `(0, 1, -5.065781)` m |
| 挂车零转角等效轴局部 Z | 2.853482 m |
| 挂车等效轴至 hook 距离 `L` | 7.919262 m |
| 挂车接地轮数 | 6 |
| 挂车转向轮 | 第 2–5 号轮，即后两轴四轮 |

连接过渡在约 0.27284 m/s（0.982 km/h）时捕获。连接前一帧原生白色框可见，下一帧 attached count 从 0 变 1 且白框隐藏。按双方 SDK hook 还原，连接首帧水平 hook 差约 0.006 m、航向差约 0.041°；这再次支持“比较两个 hook，而不是比较车体框”的判定方式。

一次 7.736 m 的前移/两段不同方向转向倒车采样中，车头最大转向输入为 0.539。挂车后两轴的单轮转角最大约 0.729°，按全部接地轮折算的等效轴转角 `beta` 范围约为 `[-0.002°, +0.356°]`。车头方向盘曾换向而 `beta` 未出现对称反号，证明挂车转向状态具有自身机械/运动响应，不能用车头输入的符号或固定比例替代实时挂车轮遥测。

随后使用完整约 100 Hz 时间序列，在方向盘基本回正的情况下分别覆盖正、负铰接角：

- 正侧两段平均速度约 1.90 km/h 和 2.78 km/h，`phi` 从 `+4.59°` 增至 `+15.37°`；拟合为 `beta = -0.032470 * phi + 0.00480°`，`R² = 0.99994`。
- 负侧平均速度约 1.24 km/h，`phi` 从 `-6.33°` 增至 `-30.47°`；拟合为 `beta = -0.034582 * phi - 0.02633°`，`R² = 0.99895`。
- 合并两侧共 2669 个运动样本后，`beta = -0.032924 * phi + 0.00051°`，`R² = 0.99896`。

这组挂车在已测范围内表现为近似奇对称、主要由铰接几何决定的自转向关系，速度变化没有破坏该关系。该系数只是本挂车样本，不能硬编码成所有挂车的常数。运行时仍应直接读取当前 `beta`；若需要长距离预测，可根据近期 `(phi, beta)` 时间序列在线估计局部斜率和可信度。没有足够双侧样本时，应冻结当前 `beta` 并增加不确定性裕量，而不是套用本次 `-0.032924` 系数。

### 3.2 首末可提升、反相转向轴样本（2026-09-11）

第二辆挂车有四轴八轮；首轴和末轴均可提升、可转向，中间两轴固定。hook 局部坐标仍为 `(0, 1, -5.065781)` m。

稳定状态如下：

| 状态 | 接地轮 | `z_effective` | `L` | `beta` |
|---|---:|---:|---:|---:|
| 首末转向轴落下 | 8 | 3.50751 m | 8.57329 m | 接近 0 |
| 首末转向轴提升 | 4 | 3.51283 m | 8.57861 m | 0 |

落下时，首轴左右轮约为 `+0.40°`，末轴左右轮约为 `-0.40°`。两端反相转向使 `average(tan(delta_i))` 几乎抵消，因此不能根据“存在明显单轮转角”就给整个挂车轴组一个同方向大 `beta`。

提升动画实际经历 `8 -> 6 -> 5 -> 4` 个接地轮；落下动画经历 `4 -> 5 -> 6 -> 7 -> 8`。混合瞬态曾产生：

| 瞬态接地轮数 | `L` | `beta` |
|---:|---:|---:|
| 5 | 8.18097 m | 约 0.070° |
| 6 | 7.91750 m | 约 0.127° |
| 7 | 8.29301 m | 约 0.054° |

稳定提升态与稳定落下态的 `L` 只相差约 0.0053 m，但动画中的混合掩码会制造最高约 0.66 m 的假性等效轴距跳变。这正是旧轨迹显示在落轴过程中至少两次抽搐的来源。

运行时必须把轮组拓扑作为原子状态：当接地掩码变化、任一提升轮的 lift 值处于过渡区，或掩码尚未稳定 0.3–0.5 秒时，继续使用上一组稳定的 `L/beta`。只有所有相关轮提升量接近稳定端点、接地掩码持续稳定后，才一次性提交新轮组并重新初始化积分器。不能逐轮即时重算，也不能用显示层曲线平滑掩盖错误物理状态。

动态传播验证：

- 提升态 4 轮固定轴倒车 4.501 m，`phi: 10.82° -> 18.51°`；实测挂车航向变化 `-7.560°`，方程预测 `-7.445°`，累计误差约 `0.115°`。
- 落下态 8 轮倒车 6.302 m，`phi: 8.36° -> 16.95°`；首末轴反相转向后整体 `beta` 仅 `0.0008°–0.0017°`。实测挂车航向变化 `-8.655°`，使用等效轴组方程预测 `-8.749°`，累计误差约 `0.094°`。

两种稳定状态都支持“接地轮约束 -> 等效轴组 -> 铰接传播”的通用方法，不需要为此挂车建立单独车型表。

落轮状态又完成了一次从近直线到高夹角的连续扫描：`phi = 2.32° -> 49.10°`，共 2565 个运动样本，平均速度约 2.35 km/h。49.10° 时首轴左右轮分别约 `+2.66°/+2.15°`，末轴左右轮分别约 `-2.63°/-2.13°`；直到 49° 未观察到明确饱和。各轮相对 `phi` 的局部线性斜率约为：

```text
wheel[0] / phi = +0.04864, R² = 0.98496
wheel[1] / phi = +0.04099, R² = 0.99507
wheel[6] / phi = -0.04813, R² = 0.98490
wheel[7] / phi = -0.04056, R² = 0.99505
```

由于首末轴近似等量反向，整个扫描中等效 `beta` 最大仅约 `0.0062°`，`L` 只在 `8.5732828–8.5732923 m` 内变化。主体铰接传播可安全使用稳定接地轮折算出的单等效轴；但轮胎扫掠、碰撞包络或轮迹可视化若需要轮级精度，仍须保留各轮真实转角，不能用接近零的整体 `beta` 反推每个轮都没有转向。

连续扫描对当前可转向挂车的直接证据只到约 49°。49–70°属于受 45°/55°软成本强烈抑制的外推区，仅在找不到低夹角路线时允许；超过 70°仍属于 fail-closed 极端折叠区。70°硬限制是产品容许值，不得误写成已由 0–70°全区间真机数据验证。

## 5. 坐标和符号约定

使用 XZ 地面平面：

- `R`：车头有效后轴参考点；
- `H`：鞍座/牵引销重合点；
- `P`：挂车等效轴组参考点；
- `theta`：车头物理车头方向；
- `psi`：挂车物理车头方向；
- `phi = wrap(theta - psi)`：铰接角；
- `a`：从 `R` 到 `H`、沿车头前向的纵向偏移；
- `b`：从 `R` 到 `H`、沿车头右向的横向偏移；
- `L`：从挂车等效轴组 `P` 到牵引销 `H` 的距离；
- `Lt`：车头有效轴距；
- `delta`：前轮等效转角；
- `kappa_t = tan(delta) / Lt`：车头按前进行程定义的有符号曲率。

项目使用：

```text
forward(q) = (sin(q),  cos(q))
right(q)   = (cos(q), -sin(q))
```

刚性约束：

```text
H = R + a * forward(theta) + b * right(theta)
H = P + L * forward(psi)
```

SCS actor 的局部 `+Z` 在本项目已验证为指向车辆物理后方，因此 telemetry actor heading 必须集中转换为物理车头方向，不能在调用点随意加减 pi。

## 6. 新的精确铰接曲率方程

定义：

```text
A = 1 - b * kappa_t
N = A * sin(phi) + a * kappa_t * cos(phi)
D = A * cos(phi) - a * kappa_t * sin(phi)
```

其中 `N` 是 hook 速度在挂车车体横向上的分量，`D` 是其在挂车车体纵向上的分量。

### 6.1 被动固定轴挂车（`beta = 0`）

挂车轴轨迹按自身行程定义的空间曲率为：

```text
kappa_trailer = N / (L * D)
```

当 `a = 0`、`b = 0`、`kappa_t = 0` 时：

```text
kappa_trailer = tan(phi) / L
```

不能退回：

```text
kappa_trailer = sin(phi) / L
```

后一个式子遗漏了挂车纵向速度分母，并且没有鞍座偏置项。小角度、短距离时差异不明显；长距离、持续转弯或较大铰接角时会累计成明显终点误差。

### 6.2 带转向轮的等效轴组

令 `beta` 为等效挂车轴组的滚动方向相对挂车车体前向的有符号转角。只使用当前接地轮：

```text
z_effective = average(z_i + x_i * tan(delta_i))
beta        = atan(average(tan(delta_i)))
L           = abs(z_effective - hook_z)
```

hook 约束仍然是 `H = P + L * forward(psi)`，但轴点 `P` 的无侧滑滚动方向变为 `forward(psi + beta)`。因此，按车头前进行程参数化时：

```text
d(psi) / ds_tractor = (N - D * tan(beta)) / L
ds_trailer / ds_tractor = D / cos(beta)
```

若在一个积分小步内把 `beta` 视为常量，挂车车体航向按挂车轴自身行程定义的空间曲率为：

```text
kappa_trailer_body =
    (N * cos(beta) - D * sin(beta)) / (L * D)
```

挂车轴真实轨迹的切向方向为 `chi = psi + beta`。当 `beta` 随行程变化时，轴轨迹曲率还必须包含：

```text
kappa_trailer_path = kappa_trailer_body + d(beta) / ds_trailer
```

ETS2 只提供当前各轮转角，没有直接提供未来自转向机构规律。因此：动态短时助手可以在每个小步冻结当前 `beta`，并随 100 ms 实时重规划不断校正；长距离一次性规划若没有 `beta(s)` 模型，不得声称对自转向挂车未来轨迹完全精确。可以把未来轮角不确定性纳入安全裕量，或通过更多实车样本拟合挂车型号无关的状态演化关系。

若以“正的倒车距离”作为积分自变量，则符号为：

```text
d(theta) / ds_reverse = -kappa_t
d(psi)   / ds_reverse = -(N - D * tan(beta)) / L
```

实现时使用中点/RK2 步进，避免欧拉积分在长距离上扩大误差。

## 7. 固定挂车曲线的精确车头反算

Reverse Planner 已不再从挂车曲率逐点使用 `asin(L*kappa)` 反推出车头角度。对挂车曲线的每一个采样点：

1. 从挂车轴点与方向计算真实挂点：

   ```text
   H_i = P_i + L * forward(psi_i)
   ```

2. 对候选车头方向 `theta_i` 计算后轴参考点：

   ```text
   R_i(theta_i) = H_i
                - a * forward(theta_i)
                - b * right(theta_i)
   ```

3. 求解车头后轴无侧滑残差：

   ```text
   midpoint = theta_(i-1)
            + 0.5 * wrap(theta_i - theta_(i-1))

   F(theta_i) = dot(
       R_i(theta_i) - R_(i-1),
       right(midpoint)
   ) = 0
   ```

4. 使用有界 Newton 迭代求根；残差、导数或结果非有限时立即拒绝候选。
5. 检查后轴位移必须沿自身倒车方向：

   ```text
   dot(R_i - R_(i-1), forward(midpoint)) < 0
   ```

6. 计算每段车头实际曲率：

   ```text
   kappa_required = wrap(theta_i - theta_(i-1))
                    / length(R_i - R_(i-1))
   ```

7. 若：

   ```text
   abs(kappa_required) > tan(maxSteer) / Lt
   ```

   则应在规划开始时淘汰整条路径，而不是先显示、行驶一半后才发现无法完成。

## 8. 倒车轨迹助手更新方式

倒车轨迹助手是“当前转向输入下的动态短时外推”，不需要复制停车位搜索器，但应复用同一真实刚体状态和传播方程。

推荐更新顺序：

1. 从 wheel telemetry 求车头有效前轴、有效后轴和 `Lt`。
2. 从 truck configuration hook 求 `a`、`b`，不要默认挂点位于后轴中心。
3. 从 trailer configuration hook 和有效轮组求 `L`；轮组包含抬升/转向轴时继续使用现有等效轴组算法。
4. 从每个接地挂车轮的实时 steering 求 `beta`；不得以车头方向盘符号代替。
5. 用实时 `effective_steering` 求 `delta` 和 `kappa_t`。
6. 初始状态使用实时 `R, theta, P, psi`，并强制两个来源计算的 `H` 在容差内一致。
7. 按第 6 节方程使用中点/RK2 连续积分，输出车头后部两条轨迹或助手既有显示对象。
8. 每步重新由刚性约束构造 `H` 和 `P`，不要把上一版视觉曲线拟合结果当作物理状态。
9. 接近 60 度铰接硬限制时保持 fail-closed；不要为了显示连续而钳制角度后继续积分。

助手升级时必须增加以下回归：

- 零偏置时验证 `tan(phi)/L`；
- 非零 `a,b` 时验证完整方程；
- 非零 `beta` 时验证滚动方向、车体航向率和 `beta -> 0` 连续退化；
- 抬升转向轴必须从当前有效轴组排除；左右 Ackermann 轮角应先平均 `tan(delta_i)`，不能直接平均角度；
- 接地掩码或 lift 动画变化时，轮组参数必须经 0.3–0.5 秒稳定判定后原子提交；过渡期间保留上一稳定轮组；
- 30 m 以上路径逐段验证后轴横向残差；
- 同一输入镜像后轨迹镜像、标量代价相同；
- 不同车长/轴距/罐车 hook 不使用统一前缘偏移；
- 极端夹角不可恢复时输出明确失败状态，不输出反向“蠕动”假轨迹。

## 9. 高级挂接状态与实测边界

一次约 100 Hz 的捕获记录显示，在同一采样帧内发生：

- attached trailer count：`0 -> 1`；
- 原生白色挂车指引框：显示 -> 隐藏；
- trailer configuration：空 -> 有效；
- SDK 精确 hook 开始输出。

该次捕获速度约 0.255 m/s（0.92 km/h）。捕获前一帧，牵引销相对鞍座约有 0.102 m 纵向误差、0.008 m 横向误差、0.86 度航向差；捕获时挂车约平移 0.098 m。

这只是一次捕获样本，不代表游戏允许的最大容差。`attached=1` 出现后应立即停止“车头接近挂车”规划，不得继续显示 X 或继续倒车箭头。

## 12. 实时规划的运算成本约束（2026-09-12）

停车规划运行在 100 ms 更新周期内，不能把离线研究用的大规模曲线枚举带入游戏线程。当前实现固定遵循：

- 常规 cubic Bézier 搜索为 `12 × 12 = 144` 条，不恢复早期 `18 × 18`；
- 常规族失败后使用 `plan_steering_profile_fallback`，直接以真实鞍座偏移、挂车轴距和 RK2 铰接传播求解三参数转向曲率曲线；
- `k1/k2` shooting 种子按 `0, -0.06, +0.06, -0.12, +0.12` 排序；规划器自有的 `k0` 先试 0，再按目标相对挂车的方向优先试 `±25%`、`±50%` 最大曲率，运行时最多五档。三者都只由当前车组几何和目标生成，不读取玩家方向盘；
- 找到第一条完整通过端点误差、转向硬上限、70°夹角、已知障碍和自身轮廓检查的路线立即返回；
- 禁止恢复 `quintic_grid` 或同类 1296 条五次曲线穷举。需要提高命中率时，应改善物理传播初值或使用跨帧 warm start，而不是扩大每帧枚举；
- `TestRuntimeCompatibility.ps1` 静态检查以上搜索结构，Stage 1A 回归 T 固定复现 2026-09-11 的 14.8 m 白框场景。

停车终点不是一次扩大整条轨迹的搜索网格。先用正常 `12 × 12` 搜索严格的框中心入口姿态；失败后只按固定顺序检查最多 12 个小范围停车姿态点，每点使用 `4 × 4` cubic 搜索，再以单个物理 shooting 种子补充，首个成功结果立即返回。这样既把停车检查容差纳入规划，又保持固定运算上限。

Release 构建下，引入停车检查点后的完整 Stage 1A 确定性回归在本机两次测得约 73–110 ms；这是整个测试进程耗时，不是游戏内单帧规划耗时，也不是跨设备硬实时保证。无论后续真机帧时间如何，都不得恢复原先的 1296 条追加穷举。

## 13. 中途短程失败与连续箭头（2026-09-12）

真机在沿有效绿线倒车后复现：挂车轴距 50% 重叠入口平面约 5.87 m，车头与挂车夹角约 0.23°，挂车与框方向仍差约 11.2°。实际姿态可以继续稳定进入任务框，但从当前帧重新要求“精确入口点和方向”时，常规候选主要在末段曲率约束失败。该情况不是目标丢失，也不是物理不可达。

运行时规则更新为：

- 严格入口仍位于任务框中心线的半挂车长度位置；只有严格姿态失败后，才沿停车框纵轴在 `-0.30..+0.70 m`、横向 `±0.35 m`、方向 `±6°` 的小矩阵内按由近到远、正负交替的 12 个检查点尝试；纵向包含少量负区，以覆盖挂车略微越过严格终点的情况，横向和角度只朝当前挂车姿态方向让步；
- 2026-09-12 的中途姿态离线回放在第一个“方向误差减半、位置不变”的检查点即由物理传播命中；这说明问题来自精确终点约束，而不是需要整体放宽曲率方程；
- 若所有停车检查点仍无法生成完整曲线，但挂车位于入口前方不超过 `max(6 m, 0.60 × 挂车长度)`、横向不超过 1.0 m、框方向误差不超过 15°且铰接角不超过 25°，才判为稳定终端导入阶段；
- 终端导入阶段不得启动红色 X 计时，改为保留最后一次有效转向误差并显示车侧方向箭头；冷启动没有历史值时显示直后倒车箭头；
- 这只是显示状态机对游戏停车区域的建模，不放宽曲线内部的转向、碰撞或 70°铰接硬约束，也不生成伪造轨迹。

车侧箭头直接使用连续转向误差：`|error| <= 1°` 显示直后；`1° < |error| < 36°` 用 smoothstep 从直后连续旋转到对应一侧；`|error| >= 36°` 保持 90°左/右箭头。回归 U/V 分别覆盖小矩阵中途姿态、固定工作量上限和五个箭头边界点。

## 14. 方向盘与完整路线彻底解耦（2026-09-12）

后续产品决定取消速度分支。无论车辆静止、蠕行或正常倒车，实时方向盘都不得进入完整路线枚举或物理 fallback 的初始曲率：

- cubic 路线从车头、挂车、任务框几何关系推导所需曲率；物理 fallback 也必须由规划器独立选择起始曲率 `k0`，不能把“与方向盘解耦”等同为“强制 `k0=0`”。`k0` 采用有界、目标方向优先的曲率种子，始终不读取玩家方向盘；
- 实时方向盘只在路线找到以后进入 `steering_correction_rad`，用于计算车侧箭头与规划方向之间的误差；
- 删除仅服务于旧 `0.10 m/s` 分支的 `truck.speed` 额外遥测订阅，避免产生无用通道和双状态边界；
- 回归 W 与运行时静态检查必须保证规划请求赋值表达式不引用 `telemetry.steering`，而箭头纠偏仍必须引用它。

真机反例（2026-09-12）：挂车轴到停车入口约 22.31 m，车头/挂车几乎共线，而挂车与目标框方向相差约 27.4°。固定 `k0=0` 时严格入口及 12 个小矩阵检查点全部失败，人工却可明显判断存在先转向再导入的路线。离线逐姿态回放确认，启用规划器自选 `k0` 后第二个方向优先种子即得到 `PARKING_REGION_PHYSICAL_FOUND`，单次测得约 12–15 ms；保持中性 `k0` 则仍为 `NO_PARKING_TERMINAL_REGION_PATH`。该回归必须永久保留，防止以后为了方向盘解耦再次误删规划器自己的首段控制自由度。

铰接角安全硬限制同步从 60°提高到 70°。70°本身允许，任何大于 70°的样本仍立即失败关闭；45°软惩罚与 55°高惩罚保持不变，使规划器仍优先远离极端折叠姿态。

## 15. 零解缓存与箭头高频跟随（2026-09-12）

真机观察到候选成功数为 0、最终显示 X 时帧率波动最大。这是所有终点检查点耗尽的最坏搜索路径，而静止姿态每 100 ms 重复相同计算没有信息增益。运行时现在缓存失败输入；车头、挂车、目标及关键挂车几何未发生实质变化时，继续推进 1 秒 X 状态计时但不再调用规划器。缓存等价阈值为位置 0.025 m、朝向 0.15°、轴距 0.01 m和转向轴角 0.001 rad；任务种子变化立即失效缓存。

车侧箭头不再被完整路线的 100 ms 重算周期限制。成功路线保存“所需方向盘角”与不含箭头的路线帧；每个 SDK `frame_end` 使用最新车头姿态和实时方向盘重新生成并原位替换箭头帧。这样路线仍受固定规划预算约束，而箭头位置、朝向和方向盘误差以遥测帧率跟随车辆，不通过提高路径求解频率换取视觉平滑。

## 16. 车侧箭头左右符号与可见顶点（2026-09-12）

SCS `effective_steering` 与本项目车头曲率约定均为正值表示方向盘向右。箭头以车头后向轴为零方向时，正 yaw 在世界坐标中反而画向左侧，因此视觉箭头必须使用 `-sign(steering_correction)`；不能把控制误差的符号原样加到后向箭头航向上。单元测试须覆盖正误差→右转箭头、负误差→左转箭头以及 ±36° 满幅边界。

绿色/红色线段模型的局部 Z 包围范围为 `[-0.18,+0.18] m`。运行时 transform 位于模型中心，而不是线段端点。构造箭头时若将箭杆和两条箭翼的中心都放在数学尖端，三个模型会各越过尖端 0.18 m，形成星形交叉。正确做法是把三条终端模型的中心沿各自线段从尖端内缩 0.18 m，使其可见端点恰好在同一数学尖端汇合。
