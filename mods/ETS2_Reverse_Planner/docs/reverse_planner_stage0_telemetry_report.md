# Reverse Planner Stage 0 — 当前遥测成果详细报告

报告日期：2026-09-09

项目目录：`ETS2_Reverse_Planner_Stage0`

当前验证游戏版本：Euro Truck Simulator 2 `1.60.1.7`（Windows x64）
项目性质：全新、独立的本地遥测与环境感知项目，不是对 Reverse Posture Assistant v0.10.8/v0.10.9 的修改或升级。

## 1. 结论摘要

Stage 0 已经建立了一条可运行、只读、可输出文本与 PNG 的本地遥测链路，并完成以下核心成果：

1. 能在 50 m 半径内读取玩家车头的世界坐标、物理朝向、速度、发动机档位、显示档位和挂车连接数量。
2. 已修正游戏世界坐标到规划器局部坐标的左右镜像问题。当前约定为：局部 `+X` 指向车辆右侧，局部 `+Y` 指向车辆前方。
3. 已确认 v0.10.8/v0.10.9 的倒挡判断依据：读取 SCS 遥测中的 `truck.displayed.gear`，值小于 0 即为倒挡。只需区分 `REVERSE` 与 `NOT REVERSE`，无需识别 A1/A2 等具体前进档。
4. 已能枚举附近挂车并读取其中心、朝向和三维包围盒；连接后的玩家挂车也能从候选中单独识别。
5. 已将“唯一可见的游戏原生 `/model/symbol/loading.pmd` 指引框所有者”确立为脱离状态目标挂车的唯一锁定途径。不存在最近距离、固定编号或人工索引回退。
6. 已定位游戏任务停车框对应的原生资源 `/model/symbol/unload.pmd` / `.pmg`，并验证它在装货点和卸货点都可出现，因此统一称为“任务停车目标”，不再区分装货/卸货。
7. 已排除另一个倒车轨迹 mod 生成的 `/model/reverse_assist/sweep_edge_blue.pmd/.pmg` 轨迹模型，避免将其误认成游戏任务停车框。
8. 游戏重启后，所有运行时地址和目标候选编号均改变，但目标挂车和任务停车框仍能依靠资源身份与所有权重新定位，说明当前方案不依赖旧地址或数组序号。

当前仍不能宣称“环境感知完成”：建筑模型边缘尚未枚举，右侧道路停滞小车等交通对象的覆盖仍不完整。因此 Stage 0 目前适合继续做目标识别和标定，不具备安全启动完整倒车路径规划的条件。

### 5.1 已读取字段

当前本地 `SCSTelemetry` 映射中使用的关键字段如下：

| 数据 | 当前偏移 | 用途 | 状态 |
|---|---:|---|---|
| 速度 | `948` | 静止判定 | `VERIFIED` |
| 世界位置 X/Y/Z | `2200/2208/2216` | 玩家车头位置 | `VERIFIED` |
| 遥测朝向 | `2224` | 转换为物理车头朝向 | `VERIFIED` |
| `truck.engine.gear` | `504` | 诊断显示，不用于倒挡主判定 | `VERIFIED` |
| `truck.displayed.gear` | `508` | `value < 0` 判定倒挡 | `VERIFIED` |
| 挂车连接数量 | 共享遥测相应字段 | 区分连接/脱离状态 | `VERIFIED` |

遥测 heading 经过 `+π` 和角度归一化后作为物理车头朝向。该处理已经通过现场朝向及 PNG 车头箭头复核。

### 5.2 激活条件

当前逻辑为：

```text
stopped      = abs(speed_mps) <= 0.05
reverseGear  = displayedGear < 0
activation   = stopped && reverseGear
```

实车证据表明，自动挡车辆静止挂入 R 时可能出现：

```text
engineGear    = 0
displayedGear = -1
```

因此不能使用 `engineGear` 替代 `displayedGear`。在重启后证据中，速度约为 0、`displayedGear=-1`，最终 `activation.valid=1`；在前进档/非倒挡证据中，`reverseGear=0`、`valid=0`。

## 8. 挂车检测和目标挂车唯一锁定

### 8.1 一般挂车枚举

通过 `game_traffic` 的玩家挂车列表，可读取 50 m 内多个挂车 actor，并从 Placement/AaBox 得到：

- entity 地址/运行时身份；
- 世界中心；
- 定向 heading；
- 宽、长、高；
- 与玩家的平面距离；
- 是否与玩家遥测挂车位置匹配。

这解决了“挂车连接后未遥测”的主要问题：连接挂车不再作为普通脱离候选处理，而是标记为 `AttachedTrailer`。

### 8.2 唯一锁定规则

脱离状态下，目标挂车的唯一正式锁定条件是：

1. 候选是 50 m 内的脱离挂车；
2. 其子模型资源包含游戏原生 `/model/symbol/loading.pmd`（并可同时看到 `.pmg/.pma`）；
3. 该原生指引模型当前为可见；
4. 可见指引框所有者恰好只有一个。

结果规则：

```text
visible owner count == 1  -> TARGET_TRAILER_VERIFIED
visible owner count == 0  -> TARGET_TRAILER_AMBIGUOUS
visible owner count > 1   -> TARGET_TRAILER_AMBIGUOUS
```

明确禁止：

- 最近挂车自动选择；
- 固定使用 D0/T0 等数组编号；
- 人工索引覆盖；
- 使用挂车距离或尺寸猜测任务归属。

因此 PNG 中的 `D0/D1/D2` 只是本次扫描的显示编号，并不是稳定 ID；`TARGET` 标签才表示通过原生指引框所有权锁定。

### 8.3 重启后的直接证据

重启后扫描发现三辆脱离挂车：

| 候选 | 距离 | 中心 X/Z | heading | 宽 × 长 × 高 | 原生指引可见 |
|---|---:|---|---:|---|---|
| D0 | 17.773 m | -12349.507 / 54659.840 | -1.539 | 2.579 × 13.904 × 3.531 m | 否 |
| D1 | 13.071 m | -12349.789 / 54650.363 | -1.529 | 2.546 × 13.886 × 3.482 m | 否 |
| D2 | 16.170 m | -12367.059 / 54663.383 | 2.516 | 2.500 × 13.705 × 3.695 m | 是 |

最终选择：

```text
index=2
source=NATIVE_LOADING_GUIDE_OWNER
confidence=VERIFIED
visibleGuideOwnerCount=1
Result: TARGET_TRAILER_VERIFIED
```

重启前同一世界位置的目标曾显示为 D0，重启后变成 D2，相关地址也由 `0x1b...` 变为 `0x1d...`。世界姿态保持在毫米级接近，而地址和编号改变。这证明锁定过程依赖当次运行中的资源身份/所有权，不依赖缓存地址或候选序号。

### 8.4 牵引销和挂接接近方向

当前牵引销估算公式为：

```text
kingpin = trailer_center + trailer_forward * (trailer_length / 2 - 1.2 m)
coupling_approach_heading = normalize(trailer_heading + π)
```

其中：

- 挂车实体中心、尺寸和 heading 为 `VERIFIED`；
- `1.2 m` 的尾端/牵引销几何余量是 `HEURISTIC`；
- 接近方向相对挂车朝向的 180°关系通过单元测试，但真实牵引销原生节点尚未找到。

所以“目标挂车是哪一辆”已经可靠，“实际鞍座应对准的精确点”仍需更多车型或原生节点验证。

## 9. 任务停车框探测

### 9.1 原生资源身份

经过绿色/白色状态、车辆驶离、前进档/倒挡以及不同货场的多轮对照，实际任务停车框被定位为：

```text
/model/symbol/unload.pmd
/model/symbol/unload.pmg
```

虽然资源名包含 `unload`，现场证明相似资源也用于装货位置。因此本项目只输出通用 `TASK PARKING TARGET`，不推断装货或卸货阶段。

当前要求资源实例：

- 资源路径精确匹配；
- 模型节点为预期的独立实例；
- 在 50 m 范围内具有唯一可用实例，才能提升为正式 K0。

### 9.2 根节点不是停车框中心

绿色停靠场景中，原生任务框根节点与已停正挂车的对照结果为：

| 测量项 | 结果 |
|---|---:|
| 根节点相对挂车中心的纵向距离 | 7.395 m |
| 横向误差 | 0.099 m |
| heading 误差 | 0.020 rad，约 1.15° |
| 根节点超过挂车后缘的余量 | 0.543 m |

因此根节点是一个有方向的后端参考点，不是矩形中心。当前中心换算为：

```text
parking_center = root + root_forward * (target_trailer_length / 2 + 0.543 m)
```

可信度：

- 资源身份：`VERIFIED`
- 根节点世界姿态：`VERIFIED`
- 目标 heading：`VERIFIED_BY_DOCKED_ALIGNMENT`
- 中心偏移：`CALIBRATED`，目前来自单一停正场景
- 入口方向 `root_heading + π`：`HEURISTIC`

### 9.3 重启后任务框结果

重启现场找到唯一任务停车模型实例：

```text
resource = /model/symbol/unload.pmd/.pmg
root     = (-12342.418, 1.027, 54664.305)
heading  = -1.539 rad
center   = (-12349.810, 1.027, 54664.537)
entry    = 1.602 rad
```

该现场中停车目标几何使用已由原生 loading 指引框锁定的目标挂车尺寸，来源标记为 `NATIVE_GUIDE_VERIFIED_TARGET_TRAILER`。

## 10. 另一个倒车轨迹 mod 的干扰与排除

早期仅根据几何形状搜索“框位”时，曾得到看似合理的 K0。但后续直接遍历资源路径证明，绿色/倒挡状态中新出现或保持的部分节点实际上是：

```text
/model/reverse_assist/sweep_edge_blue.pmd
/model/reverse_assist/sweep_edge_blue.pmg
```

它们属于另一个倒车轨迹 mod，不是游戏原生任务停车框。倒车轨迹显示时，模型节点总数曾从 451 增加至 528，增加 77 个节点，而精确的 `/model/symbol/unload.*` 实例仍保持唯一和稳定。

因此正式逻辑已经采用以下隔离原则：

- 通用模型节点簇、平行轨迹边、颜色变化或“看起来像框”的几何，一律不能成为 K0；
- 只接受精确原生任务框资源身份；
- 通用几何扫描结果输出为 `REJECTED_GENERIC_MODEL_NODE_PATTERN`；
- 另一 mod 是否显示轨迹，不应改变任务停车目标的资源锁定结果。

这是当前最重要的误报修复之一。

```text
活跃交通车辆        = 0（不代表枚举已完整）
停放/被动车辆       = 0（不代表枚举已完整）
```

### 13.3 最终结果的正确解释

日志末尾：

```text
Result: TARGET_TRAILER_VERIFIED
```

这只表示“目标挂车唯一锁定成功”，不是“全部环境感知成功”，也不是“路径已可安全规划”。任务停车框、牵引销、交通和建筑各自仍有独立可信度。

## 15. 已知风险

1. **版本风险**：内部地址链和结构偏移绑定 ETS2 1.60.1.7；游戏更新后必须重新验证签名及全部关键字段。
2. **交通漏检**：紧邻右侧停止小车曾未被捕获，这是安全相关缺口。
3. **静态环境缺失**：建筑、墙、货场设施和路缘尚未形成可规划轮廓。
4. **牵引销误差**：目前由包围盒长度和固定 1.2 m 余量推算，长货、低板或特殊挂车可能偏差较大。
5. **停车中心样本不足**：0.543 m 后缘余量来自一个绿色停正场景，需要不同货场、不同长度挂车复验。
6. **任务框唯一性**：若 50 m 内同时存在多个 `/model/symbol/unload.*` 实例，必须保持歧义状态，不能任选最近项。
7. **车头碰撞包络**：PNG 车头框已改善比例和方向表达，但尚非经车型物理边界验证的精确碰撞框。
8. **形式化审计**：当前报告基于实现、自动测试和实车证据汇总；尚未完成独立的终局代码审计。

## 16. 下一阶段建议顺序

在继续路径规划前，建议按下列顺序补齐：

1. 找到能稳定覆盖活动车辆、停车车辆和拥堵停止车辆的统一 actor/physics 枚举入口，并在高车流道路重复验证。
2. 枚举建筑、墙体、货场设施、路缘等静态碰撞对象，输出可供规划的二维 OBB、多边形或线段边界。
3. 对交通和静态对象建立去重、类别可信度和失败关闭规则；未知对象宁可标为未知障碍，不能静默丢弃。
4. 在至少三个货场、多个挂车长度上复验任务停车框根节点到中心的偏移。
5. 搜索挂车原生牵引销/挂接节点；若找不到，则按挂车类型建立可验证的标定表。
6. 给玩家车头提取真实物理包围盒，而不是仅用诊断绘图尺寸。
7. 增加跨重启、跨货场、连接/脱离、倒挡/非倒挡的自动回归证据归档。
8. 环境覆盖达到验收门槛后，再启动路径规划和碰撞检测阶段。

## 18. 当前阶段最终判定

Stage 0 已从“只能读基本车态”推进到“能可靠识别玩家状态、附近挂车、唯一任务挂车以及任务停车框原生姿态”的阶段。最关键的两类任务语义目标——目标挂车和任务停车框——均已找到可解释、可失败关闭的身份来源，并且通过游戏重启复查。

但该成果仍是**目标感知链路成立，完整环境感知链路未成立**。交通车辆漏检和建筑边缘缺失会直接影响路径安全，因此当前结论是：

```text
目标挂车锁定：READY
任务停车框定位：PARTIAL / 可继续标定
倒挡识别：READY
完整局部障碍地图：NOT READY
进入倒车路径规划：NO
```
